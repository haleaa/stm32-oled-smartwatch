# STM32 OLED 智能手表：菜单功能与蓝牙收发

基于 **STM32F103C8T6** 的裸机智能手表项目。固件使用 STM32 标准外设库开发，通过 0.96 寸 OLED、三枚按键、MPU6050、MAX30102 和蓝牙串口模块，实现时间显示、手动校时、滑动菜单、计步、心率/血氧检测、天气显示、秒表和 OLED 手电筒等功能。

> 说明：代码中的 `BLE` 命名表示“蓝牙串口数据处理”。实际常用模块为 HC-05/HC-06 一类经典蓝牙透传模块，固件本身不实现 BLE GATT 协议。

## 2. 硬件连接

### 2.1 核心器件

- 主控：STM32F103C8T6，Cortex-M3，72 MHz，64 KB Flash，20 KB SRAM
- 显示屏：0.96 寸、128×64 像素、SSD1306 兼容 OLED
- 蓝牙：HC-05/HC-06 或同类 USART 透传模块
- 六轴模块：MPU6050
- 心率血氧模块：MAX30102
- 交互输入：3 个轻触按键
- 实时时钟：STM32 片内 RTC + LSE 32.768 kHz 晶振 + BKP 备份域

### 2.2 引脚分配

以下引脚以当前源码为准。

| 模块 | 接口 | STM32 引脚 | 说明 |
|---|---|---:|---|
| OLED SCL | 软件 I2C | PB8 | OLED 时钟线 |
| OLED SDA | 软件 I2C | PB9 | OLED 数据线 |
| 蓝牙 TXD → MCU RXD | USART1_RX | PA10 | 蓝牙模块 TX 接 PA10 |
| 蓝牙 RXD ← MCU TXD | USART1_TX | PA9 | 蓝牙模块 RX 接 PA9，注意交叉连接 |
| MPU6050 SCL | 硬件 I2C2_SCL | PB10 | 100 kHz |
| MPU6050 SDA | 硬件 I2C2_SDA | PB11 | 100 kHz |
| MAX30102 SCL | 软件 I2C | PA0 | MAX30102 时钟线 |
| MAX30102 SDA | 软件 I2C | PA1 | MAX30102 数据线 |
| K1 | GPIO 上拉输入 | PB1 | 下一选项/加一，低电平按下 |
| K2 | GPIO 上拉输入 | PA7 | 上一选项/减一，低电平按下 |
| K3 | GPIO 上拉输入 | PA5 | 确认/进入/返回，低电平按下 |
| 板载 LED | GPIO 推挽输出 | PC13 | 驱动已写，但当前主程序未使用 |

接线时还需要连接共地。蓝牙模块、OLED、MPU6050 和 MAX30102 的供电电压应与实际模块要求一致，并确认所有 I/O 电平均为 3.3 V 兼容。

## 3. 软件架构

项目采用裸机前后台架构：

- **后台**：SysTick、TIM2、TIM3、TIM4、USART1 中断，只处理计时、动画节拍、接收缓存等短时任务。
- **前台**：`while(1)` 主循环统一处理按键帧、蓝牙解析、页面状态机、计步采样和 OLED 刷新。
- **显示方式**：应用层先绘制到 128×64 的显存，最后统一调用 `OLED_Update()` 输出，减少画面闪烁。

### 3.1 主循环执行顺序

1. 同步本次循环的按键事件；
2. 从蓝牙环形缓冲区取数并解析；
3. 根据当前页面状态执行主页、设置或菜单功能；
4. 在计步采样节拍到来时读取 MPU6050；
5. 将 OLED 显存刷新到屏幕。

### 3.2 定时任务

| 时基 | 周期 | 用途 |
|---|---:|---|
| SysTick | 1 ms | 按键扫描与消抖、光标闪烁、心率页面毫秒计时 |
| TIM2 | 20 ms / 50 Hz | 菜单横向滑动动画 |
| TIM3 | 10 ms / 100 Hz | 秒表百分秒计数 |
| TIM4 | 20 ms / 50 Hz | 产生计步采样节拍，实际 I2C 读取放在主循环中执行 |
| USART1 RXNE | 字节中断 | 每收到 1 字节写入 512 字节环形缓冲区 |

### 3.3 计步算法说明

当前计步使用 MPU6050 的三轴加速度：

1. 计算三轴合加速度，降低佩戴姿态影响；
2. 使用 5 点滑动平均过滤高频抖动；
3. 通过一阶低通更新动态基线；
4. 使用峰值、谷值、峰峰值和时间间隔进行判断；
5. 通过“静止、候选、步行”三态状态机确认连续步伐；
6. 连续检测到候选步伐后才正式计入步数，减少误触发。

MPU6050 本身是六轴器件，但当前 `MPU6050_GetData()` 实际只返回加速度数据，陀螺仪参数被置零；陀螺仪辅助防抖在计步模块中默认关闭，属于预留扩展。

### 3.4 心率/血氧说明

MAX30102 以 SpO2 模式同时采集红光和红外光。心率页进入后会清空采样缓存并重新配置 FIFO，采集满 100 个有效样本后执行算法：

- 通过红外光直流分量判断手指是否贴近；
- 去直流并进行滑动平均；
- 使用自相关周期估计心率；
- 使用红光/红外的交直流比值估算血氧；
- 信号质量不足时，界面继续显示 `--`，不会强行输出结果。

该功能适合课程设计、算法学习和趋势观察，不能作为医疗诊断依据。

## 4. 编译与下载

### 4.1 编译环境

- Keil MDK（μVision）
- STM32F1 系列器件支持包
- STM32F10x Standard Peripheral Library（项目已随仓库提供）
- 下载器：ST-Link、J-Link 或其他与 Keil 调试配置兼容的工具

### 4.2 编译步骤

1. 使用 Keil 打开项目根目录下的 `Project.uvprojx`；
2. 选择目标 `Target 1`，目标器件为 `STM32F103C8`；
3. 点击 **Build** 编译工程；
4. 编译成功后输出文件位于 `Objects/Project.axf`；
5. 根据使用的调试器配置下载参数后，点击 **Download** 烧录。

当前工程未启用“生成 HEX 文件”选项。如果需要 `.hex`，可在 Keil 的 Output 设置中勾选 **Create HEX File**。

## 5. 按键与页面使用

三个按键在不同页面中的含义如下：

| 按键 | 通用含义 | 特殊功能 |
|---|---|---|
| K1 | 下一项、向右切换、数值加一 | 计步页清零；天气页切换到下一页面 |
| K2 | 上一项、向左切换、数值减一 | 天气页切换到上一页面 |
| K3 | 确认/进入/执行 | 多数功能页中用于返回菜单 |

### 5.1 时间主页

上电后进入时间主页，屏幕顶部显示日期，中间显示时间，底部有“菜单”和“设置”两个入口。

- K1/K2：在“菜单”和“设置”之间切换；
- K3：进入当前反色高亮的入口。

### 5.2 设置页面

设置菜单包含返回和日期时间设置。

- K1/K2：移动焦点；
- K3：进入选项或返回上一级。

日期和时间编辑方式：

1. 焦点移动到年、月、日、时、分、秒字段；
2. 按 K3 进入编辑状态，字段闪烁；
3. K1 加一，K2 减一；
4. 再按 K3 确认并立即写入 RTC；
5. 日期页右下角的“下一步”进入时间设置。

日期调整包含闰年和每月最大天数判断，可避免出现 2 月 30 日等无效日期。

### 5.3 滑动菜单

菜单共有 6 个图标：返回、计步、秒表、手电筒、心率、天气。

- K1：切换到下一个图标；
- K2：切换到上一个图标；
- K3：打开中间选框中的功能。

图标移动由 TIM2 以 50 Hz 更新，采用逐渐逼近目标位置的方式形成自然减速效果。菜单首尾有边界限制，不会循环滚动。

### 5.4 计步页面

- 页面显示累计步数；
- 状态可以显示 `IDLE`、`READY`、`WALKING`；
- K1：清零步数并复位检测状态；
- K3：返回菜单。

计步在主循环中持续运行，不要求一直停留在计步页面。若 MPU6050 未连接，初始化后会跳过传感器读取，避免无设备时长时间等待 I2C。

### 5.5 秒表页面

底部有“开始”“暂停”“清零”三个操作项和返回图标。

- K1/K2：移动焦点；
- K3：执行当前选项。

秒表由 TIM3 每 10 ms 递增一次，显示格式为“分:秒:百分秒”。

### 5.6 手电筒页面

进入后 OLED 全屏反色显示为白屏，左上角保留返回图标。

- K3：返回菜单。

当前手电筒没有使用 PC13 LED 或外部照明灯。

### 5.7 心率/血氧页面

进入页面后，将手指轻放在 MAX30102 传感器上并保持稳定。

- 正在采集或信号不足时显示 `--`；
- 检测到有效结果后显示心率 bpm 和血氧百分比；
- 传感器未连接或 ID 校验失败时显示 `No Device`；
- K3：返回菜单。

测量时应避免强光直射、手指按压过死或大幅晃动。

### 5.8 天气页面

天气页面包含当前天气和天气预报两页。

- K1：切换到下一页面；
- K2：切换到上一页面；
- K3：返回菜单。

当前固件识别的天气字符串为：

- `SUNNY`：晴
- `CLOUDY`：多云
- `OVERCAST`：阴
- `RAINY`：雨

未收到天气数据时，页面提示等待蓝牙数据更新。如果 RTC 日期发生变化，页面会提示重新更新天气。

## 6. 蓝牙协议与手机端发送方法

### 6.1 串口参数

| 参数 | 值 |
|---|---|
| 外设 | USART1 |
| 波特率 | 9600 bps |
| 数据位 | 8 |
| 停止位 | 1 |
| 校验位 | 无 |
| 流控 | 无 |
| 推荐结尾 | `\n` |

可以使用 Android 手机上的蓝牙串口 App，也可以使用自研 App 通过 HC-05/HC-06 的 SPP 透传通道发送文本。

### 6.2 帧格式

```text
$命令,字段1,字段2,...*XX\n
```

- `$`：帧起始符；
- 命令名：`TIME`、`WEATHER`、`FORECAST`；
- 字段之间使用英文逗号 `,`；
- `*` 后接两位十六进制 XOR 校验值；
- 建议以换行符 `\n` 结尾；
- 校验范围：`$` 之后、`*` 之前的全部字节，即命令名、逗号和数据字段都参与异或。

### 6.3 时间同步帧

格式：

```text
$TIME,年,月,日,时,分,秒*XX\n
```

示例：

```text
$TIME,2026,10,5,14,30,0*11\n
```

字段范围：

- 年：4 位年份；
- 月：1～12；
- 日：按月份和闰年判断；
- 时：0～23；
- 分：0～59；
- 秒：0～59。

### 6.4 当前天气帧

格式：

```text
$WEATHER,天气,当前温度,最高温度,最低温度,湿度*XX\n
```

示例：

```text
$WEATHER,SUNNY,26,30,22,55*2C\n
```

天气字段必须使用固件支持的英文关键字：`SUNNY`、`CLOUDY`、`OVERCAST`、`RAINY`。温度使用整数摄氏度，湿度使用整数百分比。

### 6.5 天气预报帧

格式中每 5 个字段表示一天：

```text
$FORECAST,天数,天气,最高温度,最低温度,湿度,...*XX\n
```

一次最多发送 3 天。示例：

```text
$FORECAST,1,SUNNY,30,22,55,2,CLOUDY,28,21,60,3,RAINY,25,20,80*1C\n
```

### 6.6 校验值计算方法

对帧体逐字节异或。例如：

```text
帧体：TIME,2026,10,5,14,30,0
计算：'T' XOR 'I' XOR 'M' XOR 'E' XOR ',' XOR ... XOR '0'
结果：11
完整帧：$TIME,2026,10,5,14,30,0*11\n
```

手机端或脚本端应按实际发送内容重新计算校验值，不要直接照抄示例中的 `11`、`2C` 或 `1C`。

## 7. 当前版本注意事项

1. **天气数据和步数不具备掉电保存能力**：当前均保存在 RAM 中，复位后会丢失；RTC 依赖备份域和 LSE 维持。
2. **时间帧存在秒数补偿**：当前代码在收到时间帧后会把秒数字段加 4 再写入 RTC，用于抵消发送和处理延迟。
3. **蓝牙命令建议按顺序发送**：建议先发送 `TIME`，再发送 `WEATHER` 和 `FORECAST`。若后续继续完善，可在 `BLE_RefreshData()` 中根据 `Result.Cmd` 将时间处理和天气处理彻底分开。
4. **天气由手机提供**：STM32 本身没有 Wi-Fi 或网络协议栈，不直接访问互联网天气接口。
5. **MAX30102 接线以源码为准**：当前传感器软件 I2C 使用 PA0/PA1，而不是部分旧文档中提到的 PB6/PB7。
6. **心率/血氧结果仅供学习参考**：测量结果受佩戴方式、环境光、运动和传感器校准影响，不可用于医疗用途。
7. **游戏和硬件 LED 尚未接入产品流程**：`Game.c/.h` 为空文件；`Led.c` 有 PC13 驱动但没有在 `main.c` 初始化。

## 9. 可以自由扩展的方向

以下方向均适合在现有架构上继续开发：

### 9.1 新增表盘

在 `Home.c` 和 `OLED_Data.c` 中增加多套主页样式，例如：

- 指针时钟表盘；
- 大字号数字表盘；
- 同时显示天气、步数和心率的信息表盘；
- 横竖不同布局或极简模式。

### 9.2 新增菜单应用

当前菜单已经使用“图标 + 功能 ID + 页面分发”的结构。新增功能时可以：

1. 在 `OLED_Data.c` 中增加 32×32 图标；
2. 在 `Menu.c` 的菜单列表中增加功能 ID；
3. 新建独立的 `App/xxx.c/.h` 模块；
4. 在菜单分发函数中增加对应页面分支。

适合添加的功能包括闹钟、番茄钟、倒计时、日历、喝水提醒等。

### 9.3 完成游戏模块

`Game.c/.h` 已预留但当前为空。可以利用三键和 128×64 屏幕实现：

- 贪吃蛇；
-  Flappy Bird 简化版；
- 2048 简化版；
- 弹珠躲避类小游戏。

### 9.4 使用真正的硬件手电筒

`Led.c` 已经提供 PC13 输出接口，但 PC13 通常只适合驱动板载小 LED。若要驱动强光 LED，应增加三极管/MOSFET 和限流电路，并把“OLED 白屏手电筒”扩展为可选择 OLED 或外部 LED。

### 9.5 增加掉电存储

当前天气和步数复位后丢失，可扩展：

- 使用 STM32 内部 Flash 保存少量配置；
- 外接 AT24Cxx 等 I2C EEPROM；
- 保存每日步数、闹钟、表盘选择、天气更新时间和用户设置。

### 9.6 完善蓝牙协议

可以在现有文本协议基础上增加：

- 闹钟同步命令；
- 步数/心率/血氧数据回传命令；
- 手机通知提醒；
- ACK/NAK 应答；
- 严格的结尾符校验；
- 根据命令类型分别处理时间、天气和控制指令。

### 9.7 低功耗与抬腕亮屏

可以结合 MPU6050 和 RTC 实现：

- 空闲定时熄屏；
- 抬腕亮屏；
- 按键唤醒；
- 传感器低频采样；
- Stop 模式和低功耗时钟唤醒。

## 10. 项目特点总结

这个项目覆盖了嵌入式手表中较完整的一条实践链路：GPIO 输入、OLED 显存绘制、状态机 UI、RTC、硬件/软件 I2C、传感器采样、USART 中断接收、环形缓冲区、文本协议解析、定时中断和基础数字信号处理。项目模块边界较清晰，既适合作为课程设计和答辩项目，也适合继续扩展为功能更完整的裸机智能手表。
